# Natane Toon Preview (Blender アドオン)

Unity 用の **Natane Toon Shader** の基本的な見た目を、Blender の EEVEE で確認するためのアドオンです。
モデリングやテクスチャ作業の途中で「Unity に持っていくとだいたいこう見える」を確かめる用途を想定しています。
Unity の完全な再現ではありません。合わない点は末尾の「再現できないもの」にまとめています。

- 対応: Blender 4.2 LTS / 5.0（EEVEE）
- ライセンス: MIT

## インストール

### zip を作る

`Blender~` フォルダで次を実行すると、隣に `natane_toon_preview.zip` ができます。

```
python build_zip.py
```

### エクステンションとして入れる（4.2 以降・推奨）

1. `編集 > プリファレンス > エクステンションを入手` を開く
2. 右上の `∨` メニューから `ディスクからインストール...` を選び、`natane_toon_preview.zip` を指定する
   （zip を Blender のウィンドウにドラッグ＆ドロップしても入ります）

コマンドラインから入れる場合:

```
blender --command extension install-file -r user_default -e natane_toon_preview.zip
```

### 従来のアドオンとして入れる

`natane_toon_preview` フォルダを Blender の `scripts/addons` にコピーし、
プリファレンスのアドオン一覧で「Natane Toon Preview」を有効にします。
`bl_info` と `blender_manifest.toml` の両方を持っているので、どちらの方法でも動きます。

## 使い方

パネルは `プロパティ > マテリアル > Natane Toon` にあります。

1. メッシュを選び、**Natane Toon に変換 (Convert)** を押す
   - アクティブなマテリアルが「Natane Toon」ノードグループに置き換わります（マテリアルが無ければ作ります）
   - Principled BSDF のベースカラー / 画像は `_Color` / `_MainTex` に引き継ぎます
2. **シーンを Unity 寄りに設定 (Setup Scene)** を押す
   - レンダーエンジンを EEVEE、ビュー変換を Standard にし、Sun が無ければ作ります
   - AgX / Filmic のままだと色が Unity と大きくずれます
3. パネルのスライダーで調整する。名前の括弧内が Unity 側のプロパティ名です
4. アウトラインは「アウトライン (Outline)」にチェックを入れると作られます
   - 細すぎて見えないときは「プレビュー倍率」を上げてください（後述）

### Unity の .mat を読み込む

**Unity の .mat を読み込む (Import Unity .mat)** で `.mat` を選ぶと、アクティブなマテリアルに値を写します。

- `.mat` はテキスト形式（Unity の Asset Serialization が Force Text）である必要があります
- テクスチャは GUID から探します。探す場所の優先順位は次のとおりです
  1. 読み込みダイアログの「Unity プロジェクト」欄
  2. アドオンのプリファレンスの「Unity プロジェクト」
  3. `.mat` の場所から上にたどって最初に見つかった `Assets` の親フォルダ
- `Assets` と `Packages` の下の画像の `.meta` を走査して GUID の対応表を作り、Blender を閉じるまで保持します。
  テクスチャを追加・移動したら、プリファレンスの「GUID キャッシュを破棄」を押してください
- 色は sRGB の値として保存されているので、リニアに変換して設定します
- 描画モード（不透明 / カットアウト / 半透明）は、シェーダーの GUID、`RenderType` タグ、キーワード、
  `_Mode`、`_SrcBlend` / `_DstBlend`、レンダーキューの順で判定します。違っていたらダイアログかパネルで直せます
- プレビューが対応していないキーワードが有効な場合は、警告として一覧を出します

**フォルダから一括読み込み (Batch Import)** は、選択オブジェクトの各マテリアルについて
`<マテリアル名>.mat` をフォルダ（サブフォルダ含む）から探して適用します。
Blender が付ける `.001` などの連番は無視して照合します。

## Unity 向けに書き出す

Blender で調整したモデルを、Natane Toon のパラメーターごと Unity に戻すための書き出しです。
`ファイル > エクスポート > Unity (Natane Toon) (.fbx + .json)`、またはパネルの
**Unity 向けに書き出す (Export for Unity)** から実行します。

`Name.fbx` を保存先に選ぶと、次のものが並んで書き出されます。

```
Name.fbx                 モデル
Name.natanetoon.json     マテリアルごとのシェーダー名・キーワード・プロパティ
textures/                テクスチャのコピー
```

オプション:

- **対象**: 選択オブジェクトだけ / 表示中のすべて
- **FBX を書き出す**: オフにすると JSON とテクスチャだけを書き出します（`"model"` は空文字になります）
- **テクスチャをコピー**: `textures` フォルダにコピーします。中身が同じファイルは上書きしません。
  パックされた画像や Blender 内で生成した画像は PNG として保存します。
  オフの場合は元ファイルへの相対パスを書き、相対パスにできない（別ドライブの）ときは空文字になります

FBX は Unity 向けの設定で書き出します（スケール: FBX Units Scale、前方 -Z / 上 Y、リーフボーンなし、
アニメーションのベイクなし、モディファイアー適用、カメラとライトは含めない）。
アドオンが作ったアウトライン用の Solidify とマテリアルスロットは書き出しの間だけ外し、終わったら元に戻します。
アウトラインは Unity 側でシェーダーが描くので、FBX には入りません。

### 値の扱い

- **`.mat` から読み込んだマテリアル**: 読み込んだときの内容（すべての float / color / テクスチャ / キーワード、
  シェーダーの GUID、レンダーキュー、元の `.mat` の GUID）をマテリアルに保存してあり、書き出しではそれをそのまま出します。
  そのうえで、**読み込み直後から Blender のパネルで変えた値だけ**を上書きします。
  プレビューが再現しない機能のプロパティも変わらずに残ります
- **Blender で新しく作ったマテリアル**: パネルにある値と、有効にした機能に必要なキーワード
  （`_SPECULAR` / `_RIM_LIGHT` / `_MATCAP` / `_EMISSION` / `_OUTLINE` / `_NORMALMAP`）を出します。
  シェーダーは描画モードに応じて `Natane/Toon Shader`、`Natane/Toon Shader (Cutout)`、
  `Natane/Toon Shader (Transparent)` のいずれかです
- 色は Unity の `.mat` と同じ sRGB の値に戻して書きます
- 描画モードを変えた場合は、シェーダーを上の 3 つのどれかに切り替え、レンダーキューを -1（シェーダーの既定）にします
- テクスチャを差し替えた / 外した場合は、そのテクスチャの `guid` を空にします（元のテクスチャのままなら GUID を残します）

### 書き出しで持ち帰れないもの

- **Natane Toon に変換していないマテリアル**は JSON に入りません（FBX には入ります）。警告に名前が出ます
- **ノードエディターで直接つないだもの**。グループの入力に別のノードをつないだ場合、その入力は
  スライダーの値がそのまま書き出されます。書き出されるテクスチャは、アドオンが作った 4 つのテクスチャノード
  （`_MainTex` / `_MatCapTex` / `_EmissionMap` / `_BumpMap`）だけです
- **Blender 側だけの設定**: 「落ち影を受ける」、アウトラインのプレビュー倍率、ライト (Sun) の向きや色、ビュー変換
- **回り込み (`_WrapAmount`) を変えた場合**、`_ShadowNaturalness` はそのまま残ります。
  シェーダーは両方の大きい方を使うので、下げたつもりでも下がらないことがあります
- **裏面カリング**は Back (2) か Off (0) のどちらかで書きます（変えなければ元の値のままです）
- **シェイプキーのあるメッシュ**は、Blender の FBX エクスポーターの制限でモディファイアーが適用されません
- **アニメーション**は書き出しません
- 古いバージョンのアドオンで読み込んだマテリアルには保存データが無いので、新規マテリアルとして扱われます。
  `.mat` を読み込み直してください
- 「作り直す (Rebuild)」を押すと値が既定に戻るので、ほぼすべてが「変更された値」として書き出されます

## 対応しているプロパティ

| Unity | パネル / ノード入力 | 計算 |
| --- | --- | --- |
| `_Color`, `_MainTex` | 色 / テクスチャ | `albedo = _MainTex * _Color`（タイリング・オフセット対応） |
| `_WrapAmount` | 回り込み | `(N·L + w) / (1 + w)`。1 でハーフランバート。`_ShadowNaturalness * 0.35` を下限に使用 |
| `_ShadowOffset`, `_ShadowSharpness` | 影の位置 / 境界のぼかし | `smoothstep(0.5 - r, 0.5 + r, saturate(x + offset))`, `r = max(sharpness * 0.5, 0.0005)` |
| `_ShadowColor` | 影色 | `albedo * lerp(_ShadowColor, 1, shade) * ライト色` |
| `_Specular`, `_SpecularColor`, `_SpecularIntensity`, `_SpecularSize`, `_SpecularSoftness` | スペキュラ | `smoothstep(1 - size - soft, 1 - size + soft, N·H)` を加算 |
| `_RimLight`, `_RimColor`, `_RimPower`, `_RimIntensity` | リムライト | `pow(1 - N·V, power) * intensity * color` を加算 |
| `_MatCap`, `_MatCapTex`, `_MatCapIntensity`, `_MatCapBlend`, `_MatCapBlendMode` | マットキャップ | ビュー空間法線 `xy * 0.5 + 0.5` でサンプル。0 加算 / 1 乗算 / 2 置換 |
| `_Emission`, `_EmissionColor`, `_EmissionMap` | エミッション | `_EmissionMap * _EmissionColor` を加算（ライトの影響なし） |
| `_Cutoff` と描画モード | 描画モード / カットオフ | カットアウトは `alpha < _Cutoff` を捨てる。半透明はアルファブレンド |
| `_Cull` | 裏面カリング | Back のときだけカリング |
| `_BumpMap`, `_BumpScale` | ノーマルマップ | Normal Map ノード経由で N に使用 |
| `_Outline`, `_OutlineColor`, `_OutlineWidth` | アウトライン | Solidify モディファイアーによる背面法 |

合成の順番は Unity のシェーダーと同じで、拡散 → スペキュラ → リム → マットキャップ → エミッションです。

## ライティングの仕組み（設計上の判断）

EEVEE の Shader to RGB で得られるのは「照らされた結果の明るさ」で、`N·L` そのものではありません。
負の側が切り捨てられているので、後からハーフランバートや影の位置を再現することができません。
そこでこのアドオンは **`N·L` をノードで自前計算** します。

- ライトの向きと色は「Natane Toon Light」という共有ノードグループが持ちます
- その値は Sun オブジェクトの行列（ローカル Z 軸）と色・強さへの**ドライバー**で駆動します。
  Python 式を使わない単純なドライバーなので、スクリプトの自動実行を許可していなくても動き、
  Sun を回転・アニメーションさせればレンダリングにもそのまま反映されます
- 使う Sun はパネルの「ライト (Sun)」で指定できます。空の場合はシーン内で名前順に最初の Sun です。
  Sun の追加・削除はハンドラーが検知してつなぎ直します。Sun が無いときは固定の向きの白色光になります
- ライト色は `Sun の色 × 強さ` です。Unity の Directional Light の Intensity 1 が、Blender の強さ 1.0 に相当します

代わりに次のものを諦めています。

- **Sun 以外のライト（ポイント、スポット、エリア、ワールド）は陰影に影響しません**
- Sun は 1 つだけです
- 落ち影はオプションです（「落ち影を受ける」）。ライト方向を向けた Diffuse BSDF を Shader to RGB に通し、
  Sun の明るさと比べて 2 値化したマスクを陰影に掛けています。Unity には無い Blender 側だけの近似で、
  ワールドや他のライトが Sun の半分以上の明るさだと正しく判定できません。既定はオフです

## 再現できないもの

- **VRC Light Volumes、ライトプローブ、環境光 (SH)、追加ライト（ポイント / スポット）**。
  Unity ではこれらが足されるので、暗い場所や色付きの環境では結果が変わります。プレビューは Sun 1 灯だけです
- **シェーダーの 100 を超えるオプション機能のほとんど**。たとえば次のものは読み込まず、無視します:
  2 影 / 3 影、段数指定のトゥーン、ランプテクスチャ、`_ShadowBlend` などの影の詳細設定、SSS、
  2 つ目以降の MatCap、各種マスク（MatCap マスク、リムマスク、スペキュラマスク、アウトラインマスク）、
  リムの方向制御・ブレンドモード・ぼかし、MatCap の `_Glossiness` 乗算やぼかし、スペキュラ AA、
  エミッションの点滅・スクロール・グラデーション、2nd / 3rd テクスチャ、色調補正、ディゾルブ、
  距離フェード、AudioLink、ファー、ステッカー、XRay、Ghost、FakeShadow、パーティクルなど
- **アウトラインの正確な太さ**。Unity 側の太さは `_OutlineWidth * 0.1 * 奥行きスケール` で、
  奥行きスケールは Legacy モードだとカメラのニアクリップ（0.01〜0.3）に、Stable モードだと 0.05 になり、
  さらに距離補正が掛かります。プレビューは `_OutlineWidth * 0.1 * 0.05` メートルの固定値です
  （`outline.py` 冒頭の定数）。あくまで目安なので「プレビュー倍率」で合わせてください。
  ほかに次の違いがあります
  - アウトライン幅マップ、頂点カラーによる幅、手描き風、マルチカラー、ライティングの影響は非対応
  - Solidify は 1 オブジェクトに 1 つなので、幅の違うマテリアルが混ざっていると一番太い値に揃います
  - Unity はビュー空間で押し出しますが、Solidify はオブジェクト空間の法線方向に押し出します
- **加算スペキュラ・リムの細部**。式は上の表のとおりで、Unity 側のライト色の乗算やマスク、
  影の中での減衰などは入れていません
- **カットアウトのディザ / Alpha to Coverage、半透明の描画順**。Blender の描画方式に従います
- **カラーマネジメントとポストエフェクト**。ビュー変換を Standard にしても、Unity 側のトーンマッピングや
  ブルーム、ポストプロセスは再現しません
- **Cycles**。Shader to RGB を使っているので EEVEE 専用です
- **バイナリ形式の `.mat`** と、Unity 5 以前の古い YAML 形式は読めません
- `.psd` など Blender が読めない形式のテクスチャは読み込めず、警告になります

## トラブルシューティング

- **陰影が動かない / 向きがおかしい**: パネル下部の「使用中」に Sun の名前が出ているか確認してください
- **全体が白っぽい / 色が違う**: ビュー変換が Standard になっているか確認してください
- **アウトラインが見えない**: 「プレビュー倍率」を上げてください。lilToon から移行したマテリアルは
  `_OutlineWidth` がとても小さい値になっていることがあります
- **テクスチャが付かない**: システムコンソールの警告に GUID が出ます。Unity プロジェクトのフォルダ指定を確認してください
